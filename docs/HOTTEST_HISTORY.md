# 最热榜结果通道与历史读取契约

[SS-140](https://app.notion.com/p/401038a63d5a81c288aee7c1c6b1e8f3) 于2026-10-22获批交付Studio卡片，供用户交给Few Understand agent实现。唯一机器可读定义为 `catalog/hottest-history.v1.json`。本交付不创建业务Topic、消费者、物理表或网站API，不证明Few已有这些历史。

## 数据流与责任

```text
#3018 生成基础最热榜 → 最热榜 · 结果数据通道
                         ├→ 最热榜 · 更新当前榜单 → #1009 leaderboard_hottest → 原有下游
                         └→ 统一归档 · 最热榜结果 → leaderboard_hottest_history
                                                           ↓
                                               最热榜 · 查询历史与进榜时间
                                                           ↓
                                                   Grok bot网站读取与画线
```

归档卡是已有统一归档writer的结果路由，不要求新增独立归档服务。业务与归档使用两个独立消费者组，各组读取全部轮次并在自己的幂等持久写成功后提交offset；同组多个实例分摊消息不等于两个独立消费者。业务和归档延迟分别报告。传输须覆盖归档延迟和约定重放期；不按资产压缩掉不同轮次。具体Topic、Header注册项、分区策略与保留期由Few按现有机制绑定后记录，不虚构已存在的名字。

结果发布动作 `hottest.rank` 显式升级至交付动作版本3（原缺RVOL适配已使用版本2），消息schema为 `leaderboard.hottest_round.v1`；不改算法版本。原算法、权重、候选资格、每轮计算与前50展示不变，见 [HOTTEST_BOARD.md](HOTTEST_BOARD.md)。导出阶段保留截断前已经算出的全体合格候选分数与完整排名，`rank_all`为全候选名次，`rank`仅前50有值，榜外为null。这是为离榜后继续记录热度提供结果，不是扩大网页榜单。原始行情/指标归档不能代替当时已发布的最终得分与排名；不可按今天的算法/候选集合倒算过去并冒充历史。

## 消息与存储

每轮保存不可变 `snapshot_id`、原计算/截止时间、算法/覆盖版本、完整候选结果、原始指标、归一化统计与RVOL降级状态。嵌套字段和类型见catalog的 `cards[channel].fields`、`row_fields`、`message_contract`。成功非空、成功空榜、失败不可用均可辨认；失败原因要保存。大的候选集合可物理分块，但必须用批次清单/计数/校验和确认完整，不能让半轮数据触发当前榜更新或成员退出判定。

归档逻辑数据集 `leaderboard_hottest_history` 按 `snapshot_id` 幂等。允许物理拆成轮次头与 `(snapshot_id,asset_id)` 明细；全轮完成才可见。相同ID相同内容重试不重复，异内容隔离报错。保留 `calculated_at`，另记归档时间用于延迟诊断，不能把归档时间当行情时间。失败和中断留下缺口；不补零。

当前榜消费者将前50原子替换至已有#1009，沿用原行字段和15分钟过期规则，下游身份不变。成功空榜清空，失败不伪装空榜，旧结果不得当作当前成功榜；迟到轮次不能覆盖较新轮次。同一截止时间冲突的不同轮次须隔离，不能依赖字符串ID比较决定新旧。生产者须从已冻结结果可靠重试发布，重试不能重算出另一个结果。

## 历史、进榜和日视图

网站按稳定 `asset_id`、UTC `[from_at,to_at)`、`resolution=round|day`、有界游标读取。完整请求/响应字段见 `query_contract`；返回实际覆盖范围、归档水位、缺口、下一页，不只返回裸数组。Few须给出实际接口地址、身份/权限与查询性能验证；Studio的图数据接口不是该业务接口。归档可直接满足查询则复用，否则增加可重建索引/查询投影，不能维护两套独立事实来源。

- `first_observed_top50_at`：可用历史中第一次看见在榜，不随重进覆盖。
- `first_entry_at`：只在前一完整可比轮确认榜外、本轮进入前50时确认。首次开始记录已在榜，或之前是缺口，进榜时间未知，不能冒称历史首次热门。
- 本次连续段：退出重进另记起点；算法/覆盖变化、中断后的连续性标未知。历史首次元数据与证据由归档writer保存或可靠索引，裁剪原历史前保留已知首次；查询请求只读。范围查询必须考虑起点之前的依据，不能把返回的第一行当作首次进榜。
- 每轮历史支持日内曲线；日视图按Asia/Shanghai自然日选最后一个有效点，保留实际时间及日内失败/缺口。某日缺数据不填0；不以旧有效点掩盖后续不可用。
- 榜外但仍是合格候选：继续有分数，`rank=null`、`in_top50=false`。候选无效/不在覆盖内则分数未知，与榜外不同。

历史分数是每轮候选内相对交易活跃度，变化不等于绝对关注度或收益判断。保留原始指标及统计以供解释。分数线与排名线含义分开；跨版本/覆盖段标明。市场平均/中位数参考线口径尚未决定，本交付不加默认参考线。

## Few实施验收与交接

1. 核对实际结果生产者、现有注册表与共享归档writer；绑定完整消息schema、Topic与两个消费组，记录实际物理表/路径、保留与重放配置。
2. 验证成功非空/空榜、失败、中断、重复与异内容重试、乱序、分块不完整和归档积压；当前榜与归档可以独立恢复。
3. 用真实轮次验证前50与原算法完全一致、全候选最终分确实归档、离榜后有可追溯数据；缺失不补零。
4. 验证首次起始未知、确认进榜、退出重进、跨缺口/版本/覆盖段、历史裁剪与查询窗口之前的首次证据；不改写旧快照。
5. 提供可查询的真实接口与示例，验证分页一致性、日切、归档水位、缺口、权限和性能。Grok bot再据此实现曲线与首次进榜标记。
