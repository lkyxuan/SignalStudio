## 现有规则与证据边界

用户描述的旧前端 v1：heat 为注意力百分比×1.6、信号严重度之和×2.5、最高新闻重要性×34、信号条数×5、新闻条数×4、指标条数×2之和，截断到1–99。delta依次取注意力变化百分比、价格涨跌百分比、成交量变化÷10、多空信号数之差×2.5。

阶段按风险、分歧、爆发、降温、新出现及剩余方向依次判定。风险信号优先；多空都有且条数差≤1、证据≥3为分歧；delta≥8且heat≥55为爆发；delta<−1且heat≥40为降温；45分钟内刚出现、6小时窗口内且证据≤2为新出现。升温按delta、最热按heat、新出现按出现时间、降温按delta升序、分歧及风险按heat排名，证据窗口48小时。这是用户提供的规则描述，本轮未审计旧前端代码。

本仓库现有 [产品流程](../PRODUCT_WORKFLOW.md) 和 [业务表定义](../BUSINESS_TABLES.md) 仍定义演示版 total_heat：首次建档贡献100，7天半衰期，事件衰减后求和。文档说明计算器与真实评分流水尚未运行。本轮确认本地工作台与图数据API可访问，不代表榜单计算已运行。

## 共同候选设计

以下均为助手在2026-10-07提出的草案，用户尚未接受公式或参数：

- 共享带来源与时间的事件证据，五榜独立计算；允许跨榜出现，合格候选不足时不强凑50名。
- 有效讨论权重 w = 资产相关度 × 可信度 × 重要性权重。重要性可先试1、1.5、2；相关度与可信度的量表仍待定义。
- 聚合同一新闻的转载；独立观点可另计，同作者刷屏设上限。消息和由它触发的告警不重复贡献。
- 区分信息发布时间与采集时间；回放只能使用当时已收到的信息。
- 缺失不等于零，数据源断采不等于降温。来源覆盖变化需要单独记录。
- 价格、成交量作为市场背景，不替代注意力变化。Kaito等外部注意力数据不是默认免费可持续输入。
- 建档不代表市场关注；建议让建档+100退出正式热度，尚未修改原契约。

优先接入持续可采的原创公告、论坛、博客/RSS与公开讨论，并建立资产身份映射。公开行情用于解释与验证，扩大社交覆盖在后续进行。可参考 [Binance公开行情](https://developers.binance.com/en/docs/products/spot/rest-api)、[DEX Screener接口](https://docs.dexscreener.com/api/reference)、[Kaito PAYG说明](https://github.com/MetaSearch-IO/KaitoX402APIDocs)。接口可读、免费额度、商业使用条件与实际爬虫覆盖应分别确认，不能把接口文档当作采集记录。

## 共同验证方法

积累连续数据后按历史到达时间重放。每天抽查各榜前10及未入榜候选，检查误报和漏报；比较不同窗口和阈值的稳定性。先验证榜单是否准确描述关注状态，再补充未来价格表现，不能用收益率替代所有榜单的目标。

目前没有这五套候选规则的实验或回测结果。主要待改问题是delta语义混用、证据重复加分与截断、阶段优先级代替独立榜单定义。

## 2026-10-08：五榜与共享 Redis、评分表的关系（架构讨论，未批准实施）

用户询问五榜是否需要五个 Redis，以及升温/降温/最热是否只是同一个热度数的不同筛选。核对现有研究草案后，区分如下：当前 #6001 → #3005 → #1006 只定义 total_heat 演示链路（建档 +100、7 天半衰期），不是五榜的完整算法。#1006 可按 asset_id + score_key 容纳多个指标的当前值，但其当前分不能代替历史快照，也不能凭单个热度值推出观点分歧或首次出现。

助手建议：先共享一个 Redis 服务，不因五榜而创建五套 Redis 实例；按用途、指标和时间窗口分开键空间，共用可复用证据，分别保存必需的历史/聚合状态。逻辑数据集不等于独立物理 Redis，#6001 当前的原始评分事件契约也不会自动提供其他榜所需的原文、观点方向、首次发现和历史基线。只有独立容量、性能或隔离要求有证据时再考虑拆分实例。本轮未修改 Redis 或执行契约。

五榜仍需各自定义：最热看当前关注规模；升温看近期关注相对历史增长；降温看此前高位到当前的回落；新出现看首次有效发现/出现时间及证据；分歧看可比较议题的多空观点。最热、升温、降温可复用基础热度或贡献时间序列，但升温/降温不等于对当前热度简单正反排序。示例：两个资产当前均 80，一个此前 40、另一个此前 100，变化方向不同。现有草案还要求区分正常衰减、来源断采与真正关注退潮；公式、窗口和资格仍待用户确认，不将示例差值直接作为正式规则。

若以后实施五榜，可用同一当前评分表、不同 score_key 表示五种结果，按指标分别选榜；历史窗口、资格、计算时间及参数版本需另明确。当前 #3010 只以 total_heat 前 100 筛选，不能原样用于其他榜，否则会漏掉热度不高但升温很快的资产。未来需对各榜分别判断资格并按相应指标同步，或为各榜定义独立模块；这只是扩展建议。早期研究的每榜前 50 与当前热度演示前 100 属于不同阶段，未据此把其余四榜改成 100。#1007 的 3 分钟有效期也不能未经校验直接套用到更新更慢的指标。
