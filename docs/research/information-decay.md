# 信息传播、评分衰减与缓存退出：研究框架

日期：2026-10-09。状态：研究提案，未实现、未拟合、无实验结果；不是完成的实证论文。

## 问题与讨论边界

用户提出应详细研究信息的传播有效期：不同信息可配置不同半衰期，甚至采用不同衰减函数，并希望系统未来能容纳这些函数。这里记录这个产品方向；模型库、字段、参数、选型和实验方案均是助手提案，尚未构成执行契约变更。既有五榜允许独立算法，不要求统一从 total_heat 派生。

现有 `catalog/score-rollup.v1.json` 使用单指数衰减，`asset_initial_score/v1` 为 +100、半衰期 10080 分钟。`decay_policy_ref` 已表达不可变规则版本，但 `half_life_minutes` 及计算器仍绑定单指数语义；不能声称现在已支持任意函数。建档奖励也不是观察到的传播事件，其七天参数不可直接作为新闻或社交内容的实证结论。

## 必须分开的三个对象

1. **观测传播**：新出现的独立提及、转发或互动随时间的数量/速率，需要真实数据；有增长、衰减、二次爆发、曝光变化及断采。
2. **评分贡献**：系统选择让一笔已接受证据在未来保留多少权重，是产品模型，不等同于真实传播概率，也不代表信息真假、重要性或价格影响。
3. **存储保留**：什么时候可以清理 Redis；还受其他计算、审计、归档和重放去重约束，不等于评分贡献截止。

首先应决定拟合的是传播增量还是某种产品有效性。仅把曲线画得好看、拟合累计提及或提高未来收益，不能证明注意力榜的定义正确。真实传播曲线和评分权重可相关，但需要明确映射假设。

## 候选模型族

设 a 为事件年龄，a≥0；K(a) 为归一化剩余权重，初始贡献 w 的当前值为 wK(a)。以下只是可比较的数学候选，不给具体信息类别预先指定胜出模型。

| 模型 | 示例 K(a) | 形状与参数 |
| --- | --- | --- |
| 单指数 | 2^(-a/h) | h 为半衰期；每再过 h 都减半，作为现有基线 |
| 伸缩指数 | exp[-ln(2)(a/h)^β] | h 为从初始值降到一半的年龄；β>0 控制形状，β=1 回到单指数 |
| 幂律长尾 | (1+a/τ)^(-α) | τ、α>0；下降越来越慢，首次半值年龄为 τ(2^(1/α)-1) |
| 双指数混合 | p·2^(-a/h_fast)+(1-p)·2^(-a/h_slow) | 0≤p≤1，两个正半衰期；描述快、慢两部分，是候选，不宣称等同于论文完整机制 |
| 有限线性 | max(0,1-a/T) | T>0 为截止年龄；到点归零，可作为简单业务基线 |
| 固定有效窗口 | a<T 时为 1，否则 0 | 有效期内不变、到期退出；这是业务规则，不一定是传播规律 |

半衰期不应是所有函数强制共享的唯一参数。非指数函数可有“首次下降到 50% 的年龄”，但其后每隔同样时间未必再次减半。原先“5–7 个半衰期后截止”的讨论只适用于单指数基线，不能直接推广。

单调核也不会自行产生二次爆发。可先让去重后的真实新证据形成新贡献；更复杂的自激传播模型预测事件强度，需要传播历史、额外参数与验证，不能当成另一个只接受年龄的函数直接替换。重复采集、重试及补采不应重置事件年龄；补采到达前不可在历史重放中提前使用它。

## 系统如何容纳模型：接口草案

未来可由版本化策略登记模型名称、参数、计龄基准及截止规则，计算器调用经审核的模型实现。配置选择预置函数，不执行用户输入的任意代码。

候选策略信息：`policy_id/version`、`model`、`parameters`、`time_basis`、`cutoff_policy`。这里是研究中的字段概念，并非新 API/schema。

- 同一信息在不同榜中可以绑定不同策略；按“信息类别 × 评分规则/榜单”选择。类别不明确时保持可解释的兜底，不自动猜测有效期。
- 每笔贡献绑定不可变策略版本；改配置产生新版本，不悄悄改变旧事件历史。需要重算旧事件时，应是明确的再处理任务，输出可区分的结果版本。
- 起算时间必须明确：原始发布时间、首次有效观察、业务生效时间和首次入账时间含义不同。既有规则以入账 created_at 为基准，不能在升级时静默换口径。
- 校验参数单位、有限性、允许范围与模型定义域；对单调衰减模型验证 K(0)=1、K≥0、不增加，以及边界和截止行为。增长/自激模型需不同契约。
- 算法版本应覆盖输入筛选、权重、衰减及聚合，不能只记录模型名。
- 未知策略版本不能默认为单指数；暂停该项计算并明确报告，避免静默错误。
- 当前 `half_life_minutes` 必填事件协议、发布者、消费者、Redis、归档、计算器及卡片必须协同升级；保留旧版本解释器并验证历史重放一致性。

## 为什么模型会改变 Redis 方案

单指数具有 K(a+b)=K(a)K(b)，同资产、同策略的线性贡献在满足计龄和更新条件时可压缩为某一时刻的合计状态，再向未来衰减。不同策略不能直接混合。逐事件截止、撤销和追溯会增加需要保留的状态，不能只留下总分。

双指数可考虑分别保留快慢分量；一般伸缩指数或幂律不能用同样的单个总分无损推进。它们可能需要逐事件年龄、时间分桶或有误差界的近似。故算法选型应同时评估内存、计算延迟和重放成本，不能先承诺所有模型都能靠一个 Hash 总数实现。

贡献截止可以基于最大年龄、剩余权重或绝对贡献阈值，但需要比较累计误差和排名边界。许多被忽略的小贡献可能改变榜位。物理删除必须满足数据依赖及约定的归档恢复条件；必要去重状态单独保留，避免旧消息重放后重新加分。容量保护不应默默改变评分语义。

## 文献起点及适用边界

- Wu & Huberman, 2007, [Novelty and collective attention](https://pmc.ncbi.nlm.nih.gov/articles/PMC2077036/)：研究 Digg 上的关注，报告新颖性符合伸缩指数衰减。支持把单指数之外的形状列入候选，不提供本项目新闻类别的参数。
- Candia et al., 2019, [The universal decay of collective memory and attention](https://www.nature.com/articles/s41562-018-0474-5)：文化产品的群体注意力研究涉及双指数及不同记忆机制。对象和时间尺度与加密交易信息差异明显，不直接迁移其参数，也不把群体拟合当单条事件真值。
- Zhao et al., 2015, [SEISMIC](https://arxiv.org/abs/1506.02594)：利用自激点过程研究转发级联最终规模预测。提示新的传播可以影响后续传播；其任务不同于当前分数核及信息失效判定。

## 可执行的研究设计

1. 定义信息类别、去重事件单位、观测目标和类别标注标准。将建档奖励与真实传播信号分开；一个主题的转载不自动等于多个独立事件。
2. 保存发布时间、首次采集时间、后续新增互动/独立提及的时间序列、来源覆盖及删帖/缺失标记。互动累计值要处理采样间隔、计数修订及缺失；不能把缺失补零当冷却。
3. 以单指数和固定窗口作为基线，逐步比较复杂模型；按事件/主题隔离训练和验证，采用时间向前验证，防止同一新闻跨平台副本泄漏。
4. 区分尚未结束观察的事件与真正终止的事件，报告右删失、曝光差异、平台变化和类别样本量。稀疏类别先共享/收缩参数，并标明不确定性。
5. 根据明确目标选择预测误差、计数似然或校准指标；另测前列排序、人工相关性、来源断采时误判、累计截断误差、内存与计算成本。关注预测与榜单产品效用分别报告。
6. 比较“仅不同半衰期”与“不同模型族”的样本外增益。如果复杂模型没有稳定增益，保留简单模型。报告置信区间、模型选择偏差及不同市场时期的稳定性。
7. 再确定各榜策略、截止规则及模型升级流程。先影子计算对比旧规则，任何上线或执行契约改变另行明确。
